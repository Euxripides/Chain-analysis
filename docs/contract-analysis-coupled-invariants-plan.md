# 合约耦合循环不变量

承接已经批准的缺口开发。使用 contract-coupled-invariants-20261016 独立工作树，继承 funds-semantics-10 源码。前阶段已实现交易位置的空账户采集、固定父区块哈希的系统环境读取、任务共用存储读取预算、完整交易状态差异比较及证据文件；生产仍为 funds-semantics-8。

本阶段先支持有限层级、无循环依赖的局部累加器递推。源码循环继续要求零起点单调计数器、稳定的无符号整数上界及逐次加一。每个累加器每轮只能有一个受支持更新；按原始语句顺序确定一次迭代读取的是其他累加器的更新前值还是更新后值。为初始累加器值保留独立符号，推导有界次数的精确多项式闭式，并逐项证明离散差分、整数性、基例、保持、退出及整数宽度关系。

检查算术与显式 unchecked 算术分别处理。检查算术只接收可证明非负和单调的受支持表达式，验证最后一次循环体中的各次运算，防止遗漏中间溢出。unchecked 模型保留实际位宽的模运算；跨位宽和非多项式反馈关系没有充分证明时继续记录缺口。不得以固定次数展开代替任意迭代数的不变量。

修改集中在 analysis-engines/verification/loops.mjs、polynomials.mjs、新增耦合递推模块，以及 verification/state.mjs、ir/internal-returns.mjs、properties/smt.mjs 和 expression_model_eval.mjs 的摘要使用处。只有全部证明义务通过的摘要才能进入状态与返回模型。实际本地 EVM 样本覆盖前向和反向更新顺序、三四层耦合、零次迭代、检查算术的边界与回滚。unchecked 耦合递推先保留明确缺口，待投影关系证明闭合后再接入；原有独立累加器的 unchecked 模型继续回归。反馈循环、修改上界、额外副作用和不支持的位宽继续拒绝摘要。保留求解文件、原始执行及固定镜像证据。

后续继续推进命名空间存储指针、代理初始化与升级连续性、外部副作用、签名和协议经济模型。完整权限和完整协议经济模型在全部必要义务与依赖闭合前保持未完成。公共查询沿用原有累计统计起点及 2000 HTTP、1000000 credits、估算 USD 10 上限，不重置计数。
