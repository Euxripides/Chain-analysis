# EVM 状态与协议性质验证实施方案

2026-10-15。承接已批准的合约分析覆盖扩展方案第 2、3 阶段，以及本次继续推进四类剩余缺口的指令。部署基线为 funds-semantics-6，镜像 sha256:b1b1ac0f9509f75d16cc58630b51a4f7ef3f66921bbb0d953ec1432f9af95025。使用独立候选工作树，保留原工作树和历史任务。

## 目标和完成判定

新增能力分别保存命题、代码与状态身份、假设、覆盖、求解结果和原始证据。单个具体模型可以完成证明；合约整体完成要求该模型涉及的所有外部入口、状态更新、依赖和证明义务均已处理。缺失项不会通过平均分或增加成功样本抵消。

“循环归纳证明”“某笔交易的完整执行记录”“声明环境下的状态转换证明”分别标明范围。gas 可执行性、源码调用点归属和数学不变量分别验证。继续保留原有局部证明和历史结果。

## 实施顺序

1. 建立可保存的状态转换与证明义务结构，复用冻结镜像中的 Z3。保留标量、映射、别名、位宽、checked/unchecked、前后状态、成功与回滚路径，明确无法建模的节点。所有模型输出接入已有通用结果分区。
2. 为归纳可处理的循环建立初始条件、保持条件、退出性质和递减量证明。先覆盖单调计数器及仿射累加，验证溢出和循环边界；通过归纳后取得独立于展开次数的摘要。其他循环继续保存剩余路径和失败义务。
3. 给 Yul 增加字节级内存和独立存储状态模型，处理 mload/mstore/mstore8、有完整范围的复制、sload/sstore、槽别名及回滚。配合实际 opcode witness 保存复杂汇编的读写顺序、完整原始值和最终是否生效。未取得的内存范围与外部副作用有独立缺口。
4. 解析编译器 runtime source map，按指令而非字节序号建立 PC 映射；核对 PUSH、生成源码和修饰器范围。取得实际交易或完整重放的 opcode witness 后，按帧核对 CALL/STATICCALL/DELEGATECALL/CALLCODE 的 PC、目标、输入与返回，再绑定到唯一源码调用点。重复调用、递归、预编译和回滚分别验证；含混映射不绑定。
5. 将权限证明扩展为针对明确策略的全部相关入口和状态更新检查，涵盖 owner、角色及其变更、初始化、升级和外部回调。签名与多签分别检查身份、域、nonce、阈值和重放条件；缺少策略或密码学执行证据时列明义务。完整结论由全部义务闭合产生。
6. 建立账本守恒、费用、资产与份额等协议性质模型，核对全部相关状态转换与外部资产依赖。首批采用现有 ERC20、ERC4626 及自建分配/权限金标准，使用实际源码关系生成命题。协议接口和方法名称不作为证明依据。
7. 更新能力发现、报告、分页和导出。复核旧任务、权限、审计、预算和取消恢复，冻结候选源码、镜像、二进制、资产与证据后，只切换四个合约分析服务。

## 验证要求

循环使用超过原 16 次上限、零次、边界、溢出及不能归纳的负例。归纳证明分别核对初始、保持、退出和终止，反例在本地 EVM 重现；有限样本通过不替代归纳证明。

汇编检查非对齐与重叠内存、零初始化、逐字节覆盖、存储槽别名、packed 值、重复写入、STATICCALL 禁写、委托调用和祖先回滚。源码调用点检查同 selector 多处调用、同一调用点多次执行、优化开关、代理及编译器生成范围；错误绑定验收数为零。

权限与经济模型同时提供正确实现和具有绕过入口、错写字段、错误费用/取整、重放或外部依赖缺口的实现。记录每类模型的全部义务数量、已证明、反例、未知和未支持数量。任何必要义务未闭合时，该模型的 complete 为 false。

沿用上一轮金标准、运行对照、真实隔离 API/MCP、数据库、逐文件 ZIP、桌面/移动页面、审计链及旧任务检查。新增外部读取仍受累计 2000 HTTP、1000000 credits、估算 USD 10 的既有上限约束；先使用冻结源码和本地执行。只读公共链，交易发送限于本地 Anvil。

## 资源与发布

保留既有 2 CPU/2 GiB、引擎超时、工件大小和任务持久预算。新增证明按义务和时间限额执行，超时保存 unknown。opcode witness 限制指令数和字节量，截断后不得提供完整绑定或状态结论。性能门禁继续包含 ERC4626 固定样本，实际额外开销单独记录。

原 API、MCP 参数、权限、数据库结构和原主业务服务保持既有契约。新模型使用增量结果分区和能力字段；需要突破这些约束或提高生产资源时，先提交具体变更再决定。发布失败回退服务与配置，保留任务、证明文件和原始证据。

## 本次实现范围

循环归纳先覆盖零起点、单调 uint 计数器、稳定边界和迭代无关的局部仿射累加。初始、保持、退出与递减量义务全部通过后，才为返回表达式生成不受原 16 次展开上限限制的摘要。非线性递推、堆依赖和其他循环保留未完成义务，gas 可执行性单独列出。

汇编模型采用字节内存、物理存储槽和交易临时存储，记录重叠复制、packed 值、委托存储及回滚。实际 opcode 记录与符号状态模型分别保存。编译器保留内存别名、动态复制范围和未建模宿主作用会阻止对应模型闭合。

外部返回值按交易、区块、交易序号、调用帧、调用者代码与存储上下文、PC、目标、输入、返回、msg.sender、msg.value 及生效状态核对。编译器 source map 必须指向唯一源码调用点，原生币 transfer/send 也纳入 CALL 位置映射。同一调用点对应多个内部展开表达式时，保留调用点关联及表达式歧义，不生成唯一表达式替换。

权限模型检查全部可变 public/external 入口，包括实际派发的 fallback 和 receive，首批策略为 owner 身份完整性及角色管理员权限。账本模型检查全部入口的账户余额变化与 totalSupply 变化，并为单合约源码构造和初始化生成零存储起点的证明义务。反例保存具体输入和入口存储；符号入口状态的可达性与历史部署身份分别列明。

本次不将局部模型闭合提升为完整权限或协议经济证明。继承构造、代理初始化与升级、回调和外部资产、签名域与 nonce、多签阈值、协议费用、价格、取整和清算仍有独立证明义务。ERC4626 继续保存源码公式与执行检查，尚未形成完整外部资产经济模型。

跨层状态证明采用 Ethereum 区块 19000000 的公开源码合约 0x6982508145454Ce325dDbE47a25d4ec3d2311933。历史调用点检查采用原有 WETH9 复杂执行交易 0xecdc668e16ada76f439b09c9b8c2faa7b76f80244933193c7691ac797e26eae7。旧 Tether 样本继续验收原有地址权限观察；未取得编译器存储布局时，新状态模型保持未完成。
