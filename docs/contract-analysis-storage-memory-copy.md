# 存储结构体复制到内存

本能力恢复编译器确认的存储结构体到内存复制，把字段继续用于金额、收款对象和条件分析。对象和字段以原始声明身份识别，不依赖项目、方法或变量名称。

## 支持范围

源码中的显式内存声明、重新绑定、元组局部绑定和内部内存参数，可从相同 StructDefinition 的唯一完整存储投影分配新对象。支持整数、地址、布尔值、定长 bytes 和现有深度预算内的嵌套结构体。内存别名共享新对象，后续原存储写入、存储引用重绑和索引局部变量变动不改变旧副本。

每个标量字段保存 `source_storage_snapshot` 表达式，包含物理槽、偏移、字段声明、捕获的键表达式、复制点、源位置和顺序。映射键显示为 `storage_key<T>(value)`，保留定长 bytes 的左对齐等编码要求；字段显示为 `storage_at_copy<T>(copy_point, slot, byte_offset=...)`。

这些字段是复制时点的符号读取。表达式保持 `storage_value_bound=false` 和 `all_execution_paths_verified=false`。前序存储写入尚未传播为此处的数值 SSA，参数影响不能由某次实际执行结果代填。

## 保留的缺口

数组元素边界、动态字段、枚举字段、可能失败或含副作用的键、条件投影不唯一、未知分配器、汇编破坏和只读返回摘要内部的复制保持具体未解析原因。字段被丢弃或覆盖时，原有求值失败依赖继续保留。

正式状态转换解释器仍不支持内存结构体，继续报告 `STATE_SCALAR_TYPE_UNSUPPORTED`。本能力不改变完整权限、协议经济、历史状态、隐藏源码及陌生盲测的证明状态。

## 验证与交付

`p2_storage_copy_runtime.mjs` 使用一个 22 方法自有实现执行 90 笔目标交易，核对独立编译产物、实际部署代码、收款余额、全部 getter、回滚和 panic。67 个向量的金额应从保存模型与真实读取独立求得，其余 23 个向量必须保留对应缺口。相同实现的不同向量和编译配置分别记录，不计作独立业务实现。

`storage_copy_witness.mjs` 按原始编译器布局、键类型和源码映射核对实际 SLOAD；读取缺失或同一复制点存在歧义时直接失败。独立表达式求值器要求调用方提供此类存储证据，未提供时报告 `MODEL_STATE_WITNESS_UNAVAILABLE`。

私有候选另有五种编译器、两种优化配置的 200 次实际交易，以及缓存 Maker Vat 和 Uniswap Staker 源码的隔离执行。Staker 使用明确记录的 NFT 管理器测试替身，两种数量敏感性向量使用人工预置存储。Maker 的债务上限、抵押安全性和最小债务等条件仍有未解析依赖；Staker 的奖励和完整质押流程仍未证明。

新增能力沿用现有 MCP 方法、流程和工件读取接口。必须在当前候选完成实际提交、保存模型读取、执行证据对照、全部 ZIP 和数据库审计后记录 MCP 交付；私有脚本通过不构成交付。原始独立复核标准、192 项事实门槛和各项资源预算保持不变。整体质量仍为 NO_GO。
