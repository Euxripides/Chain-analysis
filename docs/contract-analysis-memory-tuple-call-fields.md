# 内存结构体字段的内部元组返回赋值

分析器根据编译器声明、参数、返回值和调用绑定，处理只读内部函数返回的标量元组写入内存结构体字段。枚举、整数、局部标量、别名对象、多个对象和反向字段排列继续使用各自的类型及声明身份。右侧全部值先被捕获，再更新目标字段；重叠目标保留未解析结果。

例如，内部函数返回错误码和金额后写入`(value.error,value.quantity)`，金额与错误码分别保留所属返回分量、分支条件和参数来源。对于`(value.error,) = division(x)`，被丢弃的第二个返回分量仍会执行。其除零失败影响后续付款，不能在仅保留错误码时消失。接收全部返回值后再覆盖金额，也保留先前调用的失败依赖。

表达式中的`SourceAggregateVersion.fields[].evaluation_group_id`指向同一次捕获的完整右侧调用表达式。同组字段共享求值依据，父版本的`evaluation_history_expression_ids`保留原调用；不同调用、分支或旧字段的失败标记分别保留。元组快照的`rhs_kind`和`rhs_expression_id`可用于核对右侧形式和表达式。上述引用均属于同一方法及源码调用上下文。

MCP沿用现有方法、表达式、数据流、权限、资金和证据查询。按方法读取`expressions`及`dataflow`可取得字段版本、共同求值表达式和未解析原因。保存模型中的输入SHA、编译器及字节码分别与实际执行材料核对。`method_details.aggregate_model_references`继续提供分页查询。

执行检查覆盖18个方法的70组输入，包括成功付款、条件回滚、除零、算术溢出、别名、取值快照、命名与嵌套返回。五个编译器各使用两种优化配置，共700笔实际交易，均核对模型字节码、独立编译字节码和部署字节码。编译器版本为0.4.26、0.5.8、0.6.12、0.7.6和0.8.30。它们是同一受控实现的编译变体。

外部或有副作用的返回、重叠字段、汇编内存影响、递归、丢弃分量及覆盖值导致的失败依赖继续输出具体缺口。现有32字段、256方法版本、2048总版本、8192聚合记录、50000源码表达式、6250增强返回表达式及其他资源限制保持原值。完整权限、协议经济及全部执行路径的证明标记维持现有状态。
