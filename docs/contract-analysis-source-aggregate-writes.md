# 源码内存结构体字段写入

规则20候选扩展已有表达式、数据流、方法详情和结论依赖，不增加MCP工具或业务路由。当前尚未完成冻结候选验收，生产继续使用既有规则8。

## 已实现范围

在编译器声明确认的内存结构体上，标量字段直接赋值产生新不可变版本。已知别名观察同一对象的新值，先前捕获的标量仍引用旧版本；引用重绑定保持旧别名的对象身份。嵌套字段使用各层声明和对象身份定位，不依赖字段、函数或项目名称。

分支两侧对象身份和标量字段可确认时，使用编译器条件表达式合并字段值，保留两个父版本。已终止分支不修改正常后继的堆。纯右侧元组和普通、互不重叠的标量字段目标先捕获全部右值，再产生字段新版本；先前捕获的标量继续保留。重叠或带副作用的字段目标仍使可能受影响的堆状态失效。条件写入目标、引用字段替换、复合赋值和自增仍保留具体缺项。

默认局部声明支持0.4.26、0.5.8、0.6.12、0.7.6、0.8.30。只在分配器已知且没有先前未知内存副作用时建立有类型的零初值和新对象身份。嵌套结构体分别分配对象，不声明具体内存偏移。其他编译器、入口未绑定参数、命名返回引用、动态字段和未知分配器继续保留缺项。

## 执行历史

每次写入保留前一版本及被覆盖的表达式。父版本图保留构造和先前写入的失败依赖；覆盖字段不会删除此前除零、溢出或调用失败的影响。未知汇编即使发生在首个结构体声明之前也被记录。未知效果之后不根据旧对象ID恢复别名。

赋值右侧可使用普通类型化表达式，或经传递检查确认不写共享内存的内部只读标量调用。可能调用失败的历史在随后覆盖时继续保留。可变内存返回摘要和外部返回绑定不在本次开放范围。

## 资源与兼容

继续使用50000总表达式、8000单方法表达式和2GiB容器限制。结构体版本单方法256、任务2048，记录8192、字段32、嵌套4层等原限制不变。被覆盖表达式的历史引用计入记录预算；超限后保留已有捕获值，并将后续读取标为未解析。

结果继续使用expressions与dataflow，方法详情沿用aggregate_model_references。能力声明为source-aggregate-v2，保留已有字段与只读返回结构。权限、隔离、分页、工件、取消和审计接口不变。

## 验证状态

隔离原型已完成5个编译器、10组配置的默认值与字段检查，以及实际部署、付款、余额、状态、事件和回滚验证。相同实现的编译配置分别记录，不作为独立业务实现或盲测。固定Compound已解析方法体没有回退；既有资金、权限等语义字段未因该探测取得验收。

冻结镜像的全量回归、独立语义审查、实际九个MCP工具、完整工件与数据库审计仍待完成。既有3056项未核实差分、192项质量NO_GO、隐藏源码和新盲测缺口、完整权限及协议经济证明继续保留。

首个冻结候选的元组反例通过5笔实际交易确认了7个旧金额和1个旧收款人错误。失败候选和全部轨迹留存。后续隔离模型已对五组纯字段元组和两个字段交换、跨对象写入正例给出精确值。

第二个冻结候选发现一元写入目标中的嵌套自增未执行扫描，实际转出2 wei却发布已解析1 wei。失败轨迹和完整工件保留。修复先扫描目标的条件、调用与下标，再处理写入；下标只扫描一次。自增数值仍保留执行顺序缺项。七个实际交易覆盖自增、自减、删除及三种下标调用，随后纳入五个编译器的冻结运行矩阵。

Compound提交源码完整保存97个方法体，但原压缩包超出128MiB限制。超大结果继续沿用既有两种无损工件格式，选择不少于16KiB的普通文本工件和不少于1KiB的返回路径；普通结果不变。完整结果逐字节还原校验必须一致，64MiB传输、128MiB展开、32MiB工件和2GiB容器限制不变。该修正不等于Compound业务语义通过。

## 字节对象与元组绑定

局部bytes引用、表达式缓存和内部返回值保留对象身份，读取时解析所属分支中的当前版本。调用参数中的字节构造先完成，再复制进入内部调用帧。调用参数和已完成调用的字节快照保留消费时的不可变版本，后续别名写入不改变历史记录。内部参数重新绑定保持局部，成功返回出口的堆状态按条件合并。

条件别名写入同时保留目标命中和未命中的状态。每个条件通过保存的表达式身份和布尔逻辑树绑定；内参继续追踪调用方捕获的标量版本、常量和取反。条件显示文字不用于判断两条路径矛盾。同名局部变量、重绑定和连续内部调用分别保留取值身份。条件身份未知时使可能受影响的对象失效；条件树限256节点、32层，超限明确记录缺项。单元素括号按原表达式处理；0.4.26、0.5.8、0.6.12、0.7.6、0.8.30的普通编译管线按已测得的从右向左顺序提交元组局部绑定。viaIR的重叠目标仍有缺项。纯元组的已知、不重叠字节下标写入可精确更新，重叠下标、结构体bytes字段别名和内容读写顺序不确定的场景仍保留具体缺项。

0.4.26低级调用中的bytes和字符串按32字节边界补齐，第一个bytes4保留四字节前缀，后续标量按类型构造32字节字。其他未支持的变长参数类型保留缺项，不再把首个参数直接当作完整调用数据。

## 超大方法视图

整个原结果超过128MiB时，先把不少于16KiB且不超过32MiB的方法详情保存为完整工件，再使用既有文本和返回路径压缩。步骤、权限、资金、状态、调用、表达式和数据流主记录全部保留。方法详情沿用后端已有的完整视图工件和分页字段引用，外部调用记录保留内联，供后端补充调用目标与依赖。普通结果逐字节不变，工件大小和容器限制不变。

当前证据仍来自隔离原型，未代替Root候选、独立业务语义审查或MCP交付验收。先前失败候选已完成本地22文件SHA及12个ZIP全部成员核验；既有3056项未核实差分、固定192项NO_GO、隐藏源码与新盲测、完整权限和经济证明仍未完成。

## 字节消费与不明汇编

字节对象的副作用分析先保留原摘要已确认的无全局影响结果，再细分原来不明的汇编。有Yul AST、外部引用全为已知标量，且所有节点与操作均可确认不读写内存、不终止执行时，不再把EXTCODESIZE等栈计算误作全局内存写入。缺少AST、指针引用、MLOAD、MSTORE、复制、调用、终止、未知内置操作及递归仍保留缺项。此调整只用于字节对象，不改变结构体和其他摘要。

0.4.26低级调用重新拼装每个bytes参数时保留原条件身份，多参数组合做条件合取并排除已证明矛盾的组合。ABI解码候选和编码产生的类型值均保存同一个条件树，引用已保存的表达式身份。条件解码后的标量公式在不能建立唯一原始参数等价关系时继续保留缺项。

私有候选已通过六笔旧版条件调用、三笔汇编与纯虚函数交易、八笔条件ABI交易，以及既有64笔业务、126笔编译器配置交易和完整Compound结果恢复。新增运行脚本固定核对部署运行字节码、条件身份、返回值或CALL内存、值与收款对象；测试数量不代替陌生业务验收。前一Root候选仍因业务转账意图回退和旧版条件缺失未通过验收，新候选必须重新验证Root、MCP和证据工件。
