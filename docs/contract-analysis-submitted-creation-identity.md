# 提交源码的构造方法身份

同一份运行代码可以由不同创建代码产生。初始化字段分别为7和9的两个合约，在关闭元数据源码哈希后具有相同运行字节码，实际部署后的slot0和getter结果分别为7和9。提交材料和initcode均不同。原隐式构造方法仅按运行代码与存储上下文计算身份，使两个创建方法和初始状态模型共用ID。

## 身份关联

提交材料存在input_sha256时，隐式构造方法把该值纳入身份。初始模型和相关证据继续引用所属构造方法。没有提交SHA的已观察地址分析保持既有身份，显式构造方法继续使用编译器声明绑定。同一份提交材料重复分析保持身份稳定。

输入身份关联处理材料之间的区分。源码构造模型仍从零存储开始，deployment_identity_verified保留false；历史创建交易、动态构造参数、代理初始化、升级与生命周期连续性继续按各自证据核对。

## 验证

运行脚本在隔离EVM实际部署两份创建代码，核对部署收据、完整运行字节码、slot0和getter返回。两份运行代码SHA256均为4b5667ba92998ecacff15d5e60734d4421cf0e1b4009ea8e09e641ba920ab90f，创建代码SHA256分别为8d969488838a433bf79a8fdad9964ba51c67679d7cc6b0a1fd6c10a93fc89f35和9c55ba7dd9475c2f79e1086657521b0bb2485b9962e3a76d4b267fa7305913b2。完整地址、交易哈希、输入、编译器和模型保存在运行工件中。

持久测试另行核对相同输入稳定、不同输入分离、既有地址分析身份、显式声明绑定及证据引用，并保留已有继承顺序、C3构造参数、不可变值、初始化约束和solver检查。实际MCP验收需核对后端接纳的输入SHA、保存方法与初始模型、分页读取、完整ZIP和审计；隔离原型证明不代替这些交付检查。
