# 合约签名随机数保护

继续已批准的权限与签名模型开发，使用 contract-permit-nonces-20261016 独立工作树，继承已验收的 funds-semantics-12。上一阶段完成命名空间存储身份与布局、所有者和角色管理、余额守恒及后端余额投影，保留 125 项引擎测试、670 项命名空间执行检查、18 组引擎与后端回归和 17 组隔离服务验收。生产服务保持 funds-semantics-8。

已有只读检查复现了具体缺口：permit 状态转换完整，但签名策略仍以普通状态变量作为 nonce 和 allowance 的根，无法识别已验证的命名空间访问函数。先让签名策略通过同一 getter 与编译器字段身份读取 nonce 和 allowance，并检查映射键与函数参数对应关系，避免将其他账户的值当作签名主体的值。

再增加覆盖全部变更入口的 nonce 保护模型。对每条完整成功路径中实际修改的账户，比较整个入口结束后的 nonce 与入口前的 nonce；同一入口中的临时写入按最终状态处理。未知存储写入、映射键无法关联及任何不完整入口均保留缺口。该模型单独说明其“最终 nonce 不递减”的命题，保留原 permit 入口的域、签名动作、nonce 消耗、deadline 和 allowance 证明。

验收覆盖普通与命名空间存储、直接访问与局部别名、规范签名、nonce 递增与溢出回滚、跨入口重置、同一入口临时清零后恢复、无关命名空间及未知原始写入。真实 EVM 使用优化开关及两套代码生成方式。重置缺陷应同时保留形式化反例和同一签名实际再次成功的交易，区分单个 permit 入口成立与整个合约的签名重放保护。

主要修改位置为 verification/signatures.mjs、签名样例、测试与执行验收脚本。若增加新的模型种类，同步能力声明、现有报告及必要的页面名称映射，保持 API、权限、分页、文件和审计接口。固定候选镜像后执行相关回归和原有必要门禁。累计公共查询仍沿用既有起点及原上限，不以新的工作树重置预算。

缓存域的历史来源、域更新与 nonce 重置的联合不变量、合约签名、多签阈值、代理初始化及升级连续性继续分别建模。完整权限和完整协议经济模型仍保持未闭合。
