# 合约命名空间存储分析

规则版本为 funds-semantics-12，候选镜像为 sha256:c0def36572929c176ad33937cf555aa89c92509e9e5479565fa33b873e48a1ed。镜像内 49 个运行文件已与本次源码逐字节核对。本次开发在 contract-namespaced-storage-20261016 独立工作树完成，生产服务继续使用 funds-semantics-8。

## 存储位置与字段身份

新增 namespace-layout.mjs，独立计算 ERC-7201 根，并从原始编译器 AST 推导字段顺序、槽位、打包偏移和映射布局。原始分析源码保持完整，用同一编译结果核对链上运行字节码；测试另行加入编译器布局探针，核对结构体、数组和动态数据占用的范围。

命名空间注解与实际存储指针分别检查。访问函数必须满足已实现的无参数、无修饰器、单次根赋值条件，赋值目标、常量及字段均通过编译器声明 ID 关联。实际根不符、额外副作用、声明冲突和不支持的指针来源保留具体缺口。继承调用按实际覆盖函数解析，有效基类访问函数不会替错误覆盖函数建立存储身份。

命名空间顶层字段保留各自的原始 AST ID。一个物理字中的所有者和初始化标志使用不同的位范围；余额映射与总量字段也分别建模。局部存储指针、内部函数参数及返回值传递这些位置。条件分支中的指针重新绑定按状态路径处理；无法确定唯一位置的源码投影不会指定一个假定槽位。带动态键的指针赋值由状态模型保存键值，源码投影保留对应缺口。

## 汇编、权限与资金核对

已知命名空间字的 SSTORE 会记录全部已建模字段的变化，包括打包字段和静态嵌套结构体。通过已知根、规范化键编码和 KECCAK 构成的映射访问接入同一物理存储数组。Solidity 与 Yul 对同一位置的读写、回滚及余额变化共同参与证明。

所有者、角色管理员及 ERC20 余额守恒模型读取经过验证的命名空间位置。后端余额投影同时核对交易前的运行时代码、实际指针验证依据及独立重算的命名空间根，然后计算具体账户余额槽。名称相同而所属命名空间不同的字段保留不同的身份。

## 已执行验证

真实本地 EVM 已完成 40 次部署，覆盖优化开关与传统、IR 两套代码生成方式。样例包括普通访问、局部别名、内部指针参数、嵌套打包字段、多命名空间、汇编余额写入、无界耦合循环写入余额、角色授权、错误根、错误继承覆盖、未授权所有者修改、额外增发及整字污染。余额、角色写入和污染交易已完成完整交易状态差异重放。

后端已用其中 36 组实际部署数据核对账户余额的物理映射槽及交易写入值，并检查错误根、错误覆盖及运行时代码变化的拒绝结果。125 项引擎测试、670 项命名空间执行检查及 18 组引擎与后端回归已通过。17 组隔离服务验收也已通过，覆盖 API、MCP、数据库、文件、审计、真实浏览器、取消恢复、崩溃接管和资源限制。结果保存在 acceptance/contract-analysis-namespaced-storage，本候选尚未部署生产。

## 后续证明范围

数组和动态数据的布局分配已有检查，其任意读写、未验证根及尚未建模的指针路径继续保留缺口。命名空间 permit 的 nonce 与 allowance 访问函数尚未接入签名策略；已有只读检查可复现状态转换完整而签名策略仍缺少字段身份的结果，后续继续补齐关联和跨入口 nonce 保护。当前构造函数模型也未建立代理初始化、升级历史及指定范围内的存储连续性证明。完整权限、完整协议经济模型、签名历史、外部资产与回调，以及价格、费用、舍入、债务和清算模型仍需继续补齐。

公共查询沿用既有累计起点，HTTP 2000 次、1000000 credits、估算 USD 10 的上限保持原值。生命周期验收使用四个独立任务；取消、恢复及崩溃接管沿用原任务预算，每个任务的最大 RPC 请求仍为 40。预算预留按这四个任务计算，验收同时核对实际任务数，防止额外任务超出预留范围。
