# 合约命名空间存储与初始化模型

继续已经批准的缺口开发，使用 contract-namespaced-storage-20261016 独立工作树，继承 funds-semantics-11 源码。前阶段已实现检查算术下的无界耦合循环不变量及状态、返回摘要，覆盖前后更新顺序、三四层依赖、非线性乘积、while 循环和窄位宽中间溢出。生产保持 funds-semantics-8。

先支持 [ERC-7201](https://eips.ethereum.org/EIPS/eip-7201) 的命名空间根、结构体布局及实际存储指针关联。注解不单独构成存储身份：需要独立计算根，并核对编译器 AST 中真实的 `.slot` 赋值、声明身份和类型。优先处理返回一个结构体存储指针、无参数、无修饰器且只执行一次已知根赋值的内部存储访问函数。未知根表达式、其他副作用、重复注解、根冲突和不支持的指针传播保留缺口。

布局从原始编译器 AST 的字段和类型推导，不改变用于运行字节码核对的源码。保留字段顺序、打包偏移、结构体对齐和映射类型；为已知但尚未建模的数组或动态数据保留正确的布局范围及明确缺口。限制类型深度、字段数和静态存储范围，拒绝越界和已知重叠。测试另外注入编译器布局探针，与独立编译结果及本地 EVM 的实际物理存储逐项核对。

顶层命名空间字段使用原字段 AST ID 作为状态根，同时保存所属命名空间、真实槽和偏移。共享一个打包字的字段仍按各自位范围读写。映射键与静态字段的别名约束沿用现有物理存储模型，避免把同一命名空间中的余额、总量、所有者和初始化标记混为一个逻辑字段。只接受已经建立身份的存储指针；内存结构体、动态指针和未经验证的访问函数不得取得存储身份。

主要修改位置为 analysis-engines 新增命名空间布局模块、source.mjs、verification/state.mjs、verification/assembly.mjs 和 verification/policies.mjs。接入局部指针别名、字段和映射访问，并让所有者、权限及守恒模型读取同一物理位置。只有字段布局和指针来源都闭合时才能生成完成的状态转换。新增布局与指针依据进入现有模型、证明和证据文件，维持 API、权限、分页和下载接口。

本地 EVM 验收覆盖普通及打包字段、嵌套结构体、映射、多个命名空间、继承访问函数、直接访问与局部别名、声明根不匹配、同名字段、错误指针类型、隐藏副作用及实际回滚。权限和守恒模型应分别证明正常入口，并在未授权写入、字段污染及不守恒写入时保留反例。固定镜像后继续执行已有循环、汇编、创建、签名、外部返回及历史重放回归，再检查真实隔离 API、MCP、数据库、文件、审计和页面。

初始化与升级的历史连续性继续单独处理。实现合约构造函数的存储写入不等于代理初始化；创建身份、委托上下文、初始化交易、升级写入和指定范围的历史覆盖必须逐项关联。命名空间布局成立后，完整权限、完整协议经济模型和代理生命周期证明仍不得自动变为完成。

公共查询沿用原有累计起点及 2000 HTTP、1000000 credits、估算 USD 10 上限，不重置统计。本阶段的开发和验收继续使用独立工作树，前阶段源码、镜像和验收证据保持冻结。
